📖 About EaseCargo

Architecture, technology decisions, and design rationale

🎯 Project Overview

EaseCargo is a Smart Container Space Matching Platform designed to connect small and medium exporters with unused capacity in partially-filled cargo shipments. The platform emphasizes route-based shipment discovery, cost efficiency, transparency, sustainability, and visual intelligence through interactive maps.

This is an academic + real-world scalable prototype that demonstrates engineering maturity while remaining 100% cost-free using only open-source tools and free services.

🧠 Fuzzy Logic Matching

The recommendation engine uses scikit-fuzzy (skfuzzy) to compute match scores. Unlike black-box ML models, fuzzy logic provides fully explainable results based on human-readable rules.

Input Variables

  • Capacity Fit (0-100): How well the shipment's remaining capacity matches the user's cargo weight. Higher = better fit.
  • Cost Efficiency (0-100): Relative cost ranking among matched shipments. Higher = cheaper.
  • Urgency (0-100): How urgent the shipping timeline is. Higher = more urgent.

Example Rules

  • "If capacity fit is good AND cost is cheap, THEN match is excellent"
  • "If capacity fit is average AND cost is moderate, THEN match is average"
  • "If urgency is high AND capacity fit is good, THEN match is excellent"

Each variable has triangular membership functions (poor/average/good) that determine the degree of membership. The fuzzy inference engine applies all rules and defuzzifies the output to produce a crisp score from 0 to 100.

🗺️ Map Design

The platform provides a focused map visualization layer for shipment tracking:

2D Tracking (Leaflet + OpenStreetMap)

  • Used for individual shipment tracking
  • Simulated progress with interpolated positions
  • Transport-mode colored route lines
  • Lightweight, fast loading
  • Dark CARTO basemap for aesthetic consistency

Future Scope

A 3D globe experience may be reintroduced in a future phase once product scope requires global route storytelling beyond operational tracking.

📐 Data Model

The platform uses a clear separation between shipment data and geographic data:

Key Design Decisions

  • Coordinates are NOT stored per shipment — a separate city_coordinates.json provides approximate centroids for 50 cities
  • 10,000 synthetic shipments generated from CSV with realistic distributions
  • Three database tables: Users, Shipments, Bookings (via SQLAlchemy)
  • Capacity reduction on booking: The booking endpoint reduces remaining_capacity_kg and returns total cost

📡 API Documentation

GET /api/cities
List all cities with coordinates
GET /api/cities/nearby?city=Mumbai&radius=500
Find nearby cities within radius
GET /api/shipments?source=Mumbai&destination=London&mode=Sea&page=1
Search and filter shipments (paginated)
GET /api/shipments/stats
Aggregate statistics and top routes
POST /api/recommend
Get fuzzy logic recommendations. Body: {source, destination, weight_kg, transport_mode?, urgency?}
POST /api/bookings
Create a booking. Body: {shipment_id, weight_kg}. GET returns 405 by design.
GET /api/bookings
List all bookings
GET /api/tracking/{id}
Simulated tracking with coordinates and progress
GET /api/sustainability
Environmental impact metrics
